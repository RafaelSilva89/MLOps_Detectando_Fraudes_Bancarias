Do notebook à operação: um roteiro de MLOps em 17 fases

Um roteiro para pegar um projeto de Ciência de Dados que vive num notebook e transformá-lo num sistema reprodutível, versionado, testado e servindo previsões. Cada fase traz: objetivo, conceitos, o que fazer, arquivos, implementação, como testar, critério de conclusão e um checklist que marca o seu progresso com quatro estados. O exemplo real é o projeto mlops_detectando_fraudes_bancarias; cada parte diz o que é REUTILIZÁVEL em qualquer projeto e o que é ESPECÍFICO do problema de fraude.

FASE 1

Entender o problema antes de mexer em qualquer arquivo

MLOps não começa no código: começa em saber o que o modelo decide, quem usa a decisão, como medir se ela é boa e quanto custa errar. Sem isso, não há como escolher métrica, regra de decisão, SLA nem monitoramento.

No seu projeto: ■ DepoisPastas e arquivos: README.md (seção do problema)
No projeto de referência · mlops_detectando_fraudes_bancarias

Implementado e validado. Problema: barrar transferências fraudulentas. Alvo binário Target com 0,17% de fraudes. Métrica principal: PR-AUC (a acurácia de "nunca é fraude" é 99,83%). Decisão: revisar ou liberar, pelo menor custo em reais (fraude perdida = valor da transação; revisão = R$ 5). Registrado no README.md, seção 2.

1.A

Objetivo da etapa

POR QUÊ

Produzir uma ficha de diagnóstico curta que responde: qual decisão o modelo apoia, qual é o alvo, como o resultado será medido e qual é o custo de cada tipo de erro.

Por que é necessário: toda escolha técnica das próximas fases depende dessas respostas. A métrica define como comparar modelos (fase 8); o custo do erro define o limiar (fase 9); o que é "funcionar" define o SLA e o monitoramento (fase 15).

Problema que resolve no MLOps: evita automatizar e versionar com perfeição um modelo que otimiza a coisa errada.

1.C

O que fazer na prática

ROTEIRO
  1. Leia o README e a introdução do notebook; anote o problema com uma frase: "o modelo ajuda X a decidir Y".
  2. Identifique o alvo e a sua distribuição (proporção de cada classe, ou faixa de valores).
  3. Escolha a métrica principal e as de apoio. Justifique por que a métrica óbvia (acurácia, R²) serve ou não.
  4. Descreva o custo de cada erro, mesmo que como premissa ("revisão = R$ 5").
  5. Defina o que é um modelo bom o bastante: o critério de sucesso.
Decisões a tomar nesta fase

Tipo de problema · métrica principal · métricas de apoio · premissas de custo · critério de sucesso. Escreva as premissas: elas viram parâmetros no params.yaml (fase 4) e podem ser mudadas sem tocar no código.

Adaptando a outros problemas

Regressão (ex.: preço de aluguel): métrica MAE ou RMSE na unidade do negócio; custo do erro costuma ser assimétrico (subestimar x superestimar). Classificação balanceada: F1 ou AUC-ROC podem bastar. Previsão de séries: MAPE/MAE por horizonte e validação sempre temporal.

1.F

Como testar

TESTE

Este teste é de leitura, não de código. Peça a alguém (ou releia no dia seguinte) e verifique se a ficha responde, sem ambiguidade, às 7 perguntas.

  • Dá para dizer qual métrica decide entre dois modelos? Se não, a fase 8 vai travar.
  • Dá para calcular o custo de um erro a partir da ficha? Se não, a fase 9 não terá regra de decisão.
  • A métrica funciona com a distribuição do alvo? (classe rara + acurácia = sinal de alerta)

2.A

Objetivo da etapa

POR QUÊ

Transformar o notebook num inventário de três listas: (1) decisões que viram código de produção, (2) estudos que ficam como pesquisa, (3) problemas que impedem a reprodução.

Por que é necessário: o requisito central da migração é preservar a lógica. Sem o inventário, é fácil trocar um algoritmo, esquecer uma remoção de duplicatas ou levar para produção um experimento que foi descartado.

def aplicar_regra(proba, valores, limiar, regra_valor=None):
    marcado = np.asarray(proba, dtype=float) >= limiar
    if regra_valor:
        marcado |= (np.asarray(valores) >= regra_valor["corte_valor"]) & (proba >= regra_valor["limiar_valor"])

def psi(esperado, atual, faixas=10) -> float:
    cortes = np.unique(np.quantile(esperado, np.linspace(0, 1, faixas + 1)))
    cortes[0], cortes[-1] = -np.inf, np.inf
    p_esp = np.histogram(esperado, cortes)[0] / len(esperado)
    p_atu = np.histogram(atual, cortes)[0] / len(atual)
    p_esp, p_atu = np.clip(p_esp, 1e-6, None), np.clip(p_atu, 1e-6, None)
    return float(np.sum((p_atu - p_esp) * np.log(p_atu / p_esp)))
